# Commissioner reliability review

The owner deferred billing on September 30, 2026 to prioritize dependable commissioner operation. Payment code is not included in this release.

## Corrected recovery paths

| Trigger | Previous behavior | Recovery behavior |
| --- | --- | --- |
| Import creation succeeds but the response is lost | Another random workflow could start | Reconcile the exact workflow ID before responding; never invent a new ID after an uncertain response |
| Two commissioners retry a failed import or schedule job | Separate successors could run; later clicks inspected only the original failure | Both callers choose the same deterministic successor and reconnect to its retained state |
| Discord dispatch fails after snapshot activation | Finalization could throw even though the import was already live | Return successful publication and separate scheduling recovery information |
| Scheduling fails or needs initialization | The recovery endpoint was not exposed in League Controls | Retry Schedule Sync and Refresh Status are next to the connection, with permission guidance |
| A commissioner changes leagues while data is loading or saving | Late import or Discord responses could overwrite the current view | Invalidate old requests, clear league-specific state and ignore late responses |
| Coaching history is read while screenshots remain queued | Controls described history as scanned without showing remaining image work | Show found submissions, image checks, report updates, last scan and stalled state |
| Session expires or commissioner permission is missing | Both could be described as a Discord sign-in problem | Distinguish FHQ sign-in from league role checks; support email or Discord accounts |

The scheduling recovery action uses the active snapshot and existing transition proof. It does not bypass season/week validation or authorize deletion based only on a button press. Existing tracked threads are reused. A proven advance still creates the new week before deleting previous tracked threads, including results.

## Validation and practical limits

Failure injection covers lost create responses, concurrent retry requests, service unavailability, late cross-league responses, double-click prevention, and publication surviving unavailable scheduling. Five of six Worker recovery cases failed against 8.1.0; the new implementation passes all six. The full release gate and deployment receipt record final test totals.

Desktop and phone browser fixtures use the actual control rendering and action functions with simulated responses. They verify one retry request for a double click, progress refresh, coaching queue visibility, and no horizontal overflow. These fixtures are not authenticated production acceptance.

No feature can guarantee an external EA/Discord service never fails. Routine recovery should remain with the commissioner, while platform service outages and code defects must be identified honestly as support issues. Scanner infrastructure failure cannot be repaired by a commissioner changing league rules. League data, export URLs and retained submissions must remain intact.

## Remaining operating acceptance before billing

- Observe the invitation-to-first-import journey with a fresh commissioner account against the actual external providers; isolated account/onboarding fixtures already cover its application logic.
- Measure import durations and failure rates across representative roster-heavy exports and consecutive weeks; no new production import was initiated by this release.
- Verify ordinary EA reconnect and retained schedule behavior during the next real account renewal, without forcing existing connections to expire.
- Observe scheduling repair and week advance in ordinary use; automated tests cover ordering and tenant isolation, but do not substitute for live Discord delivery.
- Expand structured diagnostics for importer status correlation, service health and source-data problems. The current recovery controls do not claim to automatically repair every upstream data issue.
- Resolve owner inbox confirmation of account mail and actual production identity-linking acceptance from 8.1; do not send unsolicited test messages.

Billing remains deferred until these operating gates are satisfactory. This release does not introduce a provider, paid plan, trial, payment request or entitlement enforcement.
