# Franchise HQ v5.4.8 — LD-008 Standard League Data Events

## Purpose

Provide a normalized event contract for every future module that needs to react when League Data mode, data, or state changes.

## Added events

- `league:modeChanged`
- `league:dataChanged`
- `league:stateChanged`

Each normalized event is emitted through `FranchiseHQ.events` and as a browser event prefixed with `franchisehq:`.

Browser event examples:

- `franchisehq:league:modeChanged`
- `franchisehq:league:dataChanged`
- `franchisehq:league:stateChanged`

## Event payload

```javascript
{
  reason,
  previousMode,
  requestedMode,
  activeMode,
  source,
  status,
  timestamp
}
```

The payload contains metadata only. It does not expose a mutable League Data snapshot.

## Compatibility

The existing browser event remains available:

```text
franchisehq:league-data-state-changed
```

Existing subscribers and the existing `FranchiseHQ.leagueData.subscribe()` API remain unchanged.

## Event responsibilities

- `league:modeChanged` fires when requested mode or resolved active mode changes.
- `league:dataChanged` fires when the active source/snapshot identity or record counts change.
- `league:stateChanged` fires once for every meaningful notification generated by the League Data State Manager.

## Files changed

- `index.html`
- `league-engine/data-state.js`

## Non-goals

This release does not add roster rendering, standings, statistics, imports, live synchronization, or UI redesigns.
